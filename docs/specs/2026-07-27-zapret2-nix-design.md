# zapret2-nix — дизайн v0.1

Дата: 2026-07-27
Статус: принят, реализован в v0.1

## Задача

Дать пользователю NixOS обход DPI по принципу «поставил → выбрал готовое →
работает», не заставляя разбираться во внутренностях zapret. При этом система
должна оставаться декларативной, а проект — полезным не только автору.

## Что уже существует (обследование)

| Компонент | Состояние |
|---|---|
| `bol-van/zapret` (v1) | Зрелый, v72.13. В nixpkgs есть пакет **и модуль** `services.zapret` |
| `bol-van/zapret2` | Новое поколение, v1.0.3, активная разработка. В nixpkgs **есть пакет, модуля НЕТ** |
| `Snowy-Fluffy/zapret.installer` | 960★, GPL-3.0, **заморожен** автором |
| `Snowy-Fluffy/zapret.cfgs` | Стратегии для v1, **без лицензии** |
| `Aver1s/zapret-nixos` | 2★, форк другого инсталлера |

Ключевые выводы обследования:

1. **Форк инсталлера бессмысленен.** ~70% его кода — детект дистрибутива,
   выбор iptables/nftables, генерация юнитов, установка в `/opt`. На NixOS всё
   это решается декларативно и не нужно.
2. **Целимся в zapret2.** В нём стратегии вынесены из C в Lua, поэтому их
   может писать не только C-разработчик. Именно из-за этого сдвига автор
   `zapret.installer` заморозил проект. Строить новое на v1 — ставка на
   уходящее поколение.
3. **Лицензионная чистота.** Стратегии `zapret.cfgs` без лицензии
   переиспользовать в публичном репозитории нельзя. Lua-стратегии самого
   zapret2 — MIT, на них строить можно.
4. **Настоящая дыра — модуль.** `services.zapret2` не существует, а
   `services.zapret` для v1 [прямо отказывается настраивать nftables](https://github.com/NixOS/nixpkgs/blob/master/nixos/modules/services/networking/zapret.nix).
5. **Автоподборщик уже есть в апстриме** — `blockcheck2`, и он упакован в
   nixpkgs. Писать свой перебор стратегий не нужно.

## Принятые решения

| Решение | Обоснование |
|---|---|
| Целевой движок — **zapret2** | Будущее проекта; Lua-стратегии; дыра в nixpkgs |
| Модель — **гибрид** | Пресеты декларативно, активный — runtime. Стратегии протухают, `nixos-rebuild` на каждую пробу неприемлем |
| Объём v0.1 — **модуль + пресеты** | Без модуля TUI нечем рулить. TUI и автоподбор — v0.2 |
| Структура — **один репозиторий** | Разделить на два всегда успеем; для непроверенного проекта это преждевременно |
| Лицензия — **GPL-3.0-or-later** | Strong copyleft закрывает реальный риск (форк в чужой дистрибутив без отдачи). AGPL не даёт ничего: у системного модуля нет SaaS-поверхности, зато трения больше |

## Архитектура

```
flake.nix                 → nixosModules, lib, checks
lib/
  types.nix               → контракт пресета (presetType, profileType)
  render.nix              → пресет → conf-файл (чистая функция)
  ports.nix               → извлечение портов из пресетов
modules/
  zapret2.nix             → services.zapret2: опции, юнит, состояние
  firewall.nix            → nftables / iptables бэкенды
presets/*.nix             → стратегии как чистые данные
tests/                    → контракт пресетов + VM-тесты обоих бэкендов
```

### Границы (SRP)

| Слой | Меняется когда | Не знает про |
|---|---|---|
| `presets/` | DPI поменялся (часто) | systemd, firewall |
| `lib/` | меняется формат конфига zapret2 | систему |
| `modules/zapret2.nix` | обновился zapret2 (редко) | конкретные стратегии |
| `modules/firewall.nix` | сменился firewall-стек (редко) | Lua и стратегии |

### Инверсия зависимостей

Модуль **не импортирует** конкретные пресеты. Он зависит от контракта
`presetType`, а пресеты приходят через опции:

- `presetLibrary` — вся библиотека, можно подменить целиком;
- `extraPresets` — свои пресеты, одноимённые перекрывают библиотечные.

Следствия: пользователь с экзотическим провайдером не форкает проект, а сам
модуль пригоден к переносу в nixpkgs без нашей библиотеки.

### Единый источник правды

| Что | Источник |
|---|---|
| Доступные пресеты | `/etc/zapret2/available/*.conf` (nix store, декларативно) |
| Активный пресет | `/var/lib/zapret2/active.conf` (симлинк) |
| Порты для firewall | **выводятся из фильтров пресетов** |

Последнее принципиально: отдельная опция портов означала бы второй источник
правды и однажды дала бы «пресет чинит 443, а в очередь уходит 80». Там, где
вывод невозможен (`*`, `~`), модуль требует явного указания портов через
assertion с внятным сообщением, а не молча делает неправильно.

## Поток данных

```
presets/*.nix (данные)
  → presetType (валидация на eval)
  → render (conf-текст)
  → /etc/zapret2/available/<name>.conf (store)
  → /var/lib/zapret2/active.conf (симлинк, runtime)
  → systemd zapret2.service: nfqws2 @active.conf
  ↑
firewall.nix: порты из пресетов → NFQUEUE qnum
```

## Существенные технические детали

Проверено на nfqws2 v1.0.x перед реализацией:

- `@file` должен быть **единственным** аргументом — значит `--qnum` и прочее
  кладём внутрь файла, а не в `ExecStart`;
- conf поддерживает комментарии `#` и пустые строки;
- профили разделяются `--new`, имя задаётся как `--new=<name>`;
- пакет собран с `libsystemd`, `sd_notify` присутствует → `Type=notify` корректен;
- **`MemoryDenyWriteExecute` включать нельзя**: стратегии исполняет LuaJIT,
  которому нужна W+X-память под джит-код.

## Обработка ошибок

Assertions на этапе eval (ошибка при сборке, а не при использовании):

- пустой `presets`;
- неизвестное имя пресета — с перечислением доступных;
- `defaultPreset` вне `presets`;
- пресет без профилей;
- неразрешимые порты без явного переопределения.

Runtime:

- `preStart` чинит повисший симлинк, если активный пресет исчез из конфигурации
  после пересборки (иначе служба не поднялась бы);
- `Restart=on-failure`;
- правила iptables снимаются в `extraStopCommands` — сеть не остаётся с
  правилами, отправляющими трафик в мёртвую очередь.

## Тестирование

| Тест | Что проверяет |
|---|---|
| `presets-eval` | Контракт + **разбор конфига настоящим `nfqws2`** (ловит опечатки в опциях) |
| `nftables` (VM) | Служба, правила, переключение, восстановление, снятие правил |
| `iptables` (VM) | То же самое — проверка взаимозаменяемости бэкендов (LSP) |

`nft -c` локально недоступен (требует netlink), поэтому синтаксис nftables
проверяется именно VM-тестом.

## Осознанно не сделано в v0.1

- **TUI с автоподбором** — v0.2. Пока: `blockcheck2` для поиска стратегии,
  `zapret2ctl` для переключения.
- **Автоматические хостлисты** (antifilter/antizapret) — требуют сети во время
  сборки либо сервиса обновления; отдельная задача.
- **Несколько одновременных инстансов** — шаблонный юнит апстрима это
  позволяет, архитектура заложена, но в v0.1 один активный пресет.
